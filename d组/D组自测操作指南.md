# D 组自测操作指南（Windows 自带 tftp + clumsy）

> 场景：单机回环测试。服务器 = `tftp-server`（UDP 69 + 管理台 8080）；客户端 = Windows 自带 `tftp.exe`；损伤注入 = clumsy（管理员运行）。
> 预计总耗时：**30–60 分钟**（D1/D2/D5 视客户端超时特性而定）。
> 结论判定标准：每种损伤下**传输必完成、服务器重传次数 > 0、文件 MD5 与基准一致**。

---

## ⓪ 开始前准备（一次性，约 5 分钟）

**1. 启动服务器（必须先于 clumsy）**

```bat
cd /d "C:\Users\Atopos Yellow\Downloads\计网实验\tftp-server\tftp-server"
python server.py
```

浏览器打开 `http://127.0.0.1:8080` → 确认状态灯"运行中"。

**2. 设置页临时调参（测完必须改回！）**
网页"设置"页：

- **超时时间（秒）**：`2.0` → 改为 `**0.5**` → 保存
（丢包后每等一轮就是一个超时周期；0.5s 能让损伤测试快 4 倍。**测完恢复 2.0**）
- 如果做 D6：**最大重传次数** `6` → 临时改 `**15**`（测完恢复 6）

**3. 管理员运行 clumsy**
右键 `C:\Users\Atopos Yellow\Downloads\计网实验\clumsy\clumsy.exe` → **以管理员身份运行**。

- **Filter 保持默认的 loopback 预设**（`outbound and ip.DstAddr >= 127.0.0.1 and ip.DstAddr <= 127.255.255.255`）
- **把每一行的 Inbound 勾选全部取消**（窗口底部 NOTICE：回环抓包不能含 inbound 条件；只勾 Outbound = 双向都受损，演示效果反而更全面）

**4. 测试文件与基准（均已就位，无需生成）**


| 文件         | 位置           | 大小     | 基准 MD5                             | 用于          |
| ---------- | ------------ | ------ | ---------------------------------- | ----------- |
| dsmall.bin | 服务器 `files\` | 1 MB   | `b6d81b360a5672d80c27430f39153e2c` | D1/D3/D5 下载 |
| d6src.bin  | 服务器 `files` | 256 KB | `ec87a838931d4d5d2e94a04644788a55` | D6 下载       |
| usmall.bin | 客户端测试目录      | 512 KB | `59071590099d21dd439896592338bf95` | D2/D4 上传    |


**5. cmd 进入客户端目录**

```bat
cd /d "C:\Users\Atopos Yellow\Downloads\计网实验\客户端测试目录"
```

## ① 每个用例的固定五步循环

```
1. clumsy：勾选函数 → 填参数（只勾 Outbound）
2. 点 Start
3. cmd 跑传输命令
4. 传输结束 → clumsy 点 Stop
5. 收证据三件套：
   ① certutil 比对 MD5
   ② 网页"传输"页 → 该行详情抽屉（重传次数 / 吞吐量 / MD5）截图
   ③ "文件与日志"页筛选"重传"看日志原文 → 截图
   → 登记进《实验验收记录表.md》
```

> ⚠️ 换下一个用例前，先把当前函数的勾**取消**，避免损伤叠加。
> ⚠️ tftp.exe **不覆盖已存在的本地文件**：输出名已存在会报"无法写入本地文件"——先删旧文件或换个输出名。

### D3 · 延迟 200ms · 下载（预计 3 分钟，**用观察法，别干等传完**）


|        |                                                                                             |
| ------ | ------------------------------------------------------------------------------------------- |
| clumsy | ☑ Lag，Delay(ms) = **200**，只勾 Outbound → Start                                               |
| 命令     | `tftp -i 127.0.0.1 GET dsmall.bin d3.bin`                                                   |
| 操作     | 开着网页**概览页**看"活动传输"的实时速率：从 ~600 KB/s **暴跌到 ~2.5 KB/s** → 截图 → **clumsy 点 Stop** → 传输瞬间加速跑完 |
| 判定     | MD5 = `b6d81b36…`；速率截图形成"损伤→恢复"对比                                                           |
| 原理     | 锁步协议每 512B 一个往返，双向各 200ms → 每块 0.4s；干等 1MB 传完要 ~14 分钟，不必等                                  |

## ④ 常见坑速查


| 现象                      | 原因 / 处理                                                                                                    |
| ----------------------- | ---------------------------------------------------------------------------------------------------------- |
| clumsy Start 点了没效果      | 没用管理员身份运行（必须右键→以管理员身份运行）                                                                                   |
| 传输秒完成、重传 = 0            | Start 晚于传输开始 / 方向勾了 Inbound（回环必须只勾 Outbound）。<strong>自检</strong>：Start 后执行 `ping -n 20 127.0.0.1`，应丢 ~2 个；0 丢失 = 注入未生效 |
| 报"无法写入本地文件"             | 输出文件已存在（tftp.exe 不覆盖）→ 先删旧文件或换输出名                                                                          |
| 传输极慢 / 像卡住              | D3 属正常（延迟就是要它慢）；其他用例若异常慢→确认超时已调 0.5、或换更小文件                                                                 |
| D6 中途失败                 | 30% 双向损伤的预期行为：读失败原因 → Stop → 重试；或临时把重传次数再调高                                                                |
| 客户端报 timeout 连不上        | 服务器控制台是否开着、网页状态灯是否"运行中"、命令里 Host 是否 127.0.0.1                                                              |
| 上传报 File already exists | 上次 F2 测试的"允许覆盖"开关没恢复 → 设置页勾回并保存                                                                            |
