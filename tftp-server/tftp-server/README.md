# TFTP 服务器（Socket 编程实验）

《计算机通信与网络》Socket 编程实验 —— 基于 **Python 标准库**（纯 `socket` 手写 UDP 协议逻辑，零第三方依赖）实现的 TFTP 服务器，严格遵循 **RFC 1350**，附带 **Web 图形管理台**（选做：GUI）、**每请求一线程的并发模型**（选做：多线程）与 **块号回绕的大文件传输**支持。

---

## 1. 快速开始

### 环境
- Windows / macOS / Linux 均可，**Python 3.8+**，无需安装任何第三方包。

### 启动（Windows 实验机）
```bat
cd tftp-server
python server.py
```
启动后：
- **TFTP 服务**：`udp://0.0.0.0:69`（Windows 无特权端口限制，可直接绑定）
- **Web 管理台**：浏览器打开 <http://127.0.0.1:8080>
- 首次运行 Windows 防火墙弹窗时，勾选"专用网络"并允许访问。

### 用标准 TFTP 客户端验证
```bat
:: Windows 自带客户端（需在"启用或关闭 Windows 功能"中勾选 TFTP 客户端）
tftp -i 127.0.0.1 GET hello.txt got.txt        :: 下载
tftp -i 127.0.0.1 PUT photo.jpg                :: 上传（放到服务器根目录）

:: 或用 curl
curl tftp://127.0.0.1/hello.txt -o hello.txt   :: 下载
curl -T file.bin tftp://127.0.0.1/file.bin     :: 上传
```
也可使用 Tftpd64 的客户端功能（可选 netascii / octet 模式）。

### macOS / Linux 调试
69 为特权端口，用非特权端口启动：
```bash
python3 server.py --port 1069 --web-port 8080
curl tftp://127.0.0.1:1069/hello.txt -o hello.txt
```

### 命令行参数（均可覆盖 config.json）
```
--port 69          TFTP UDP 端口        --web-port 8080   Web 端口
--root ./files     服务器根目录          --timeout 2.0     收包超时（秒）
--retries 6        重传次数上限          --log-level INFO  控制台日志级别
```

## 4. 设计要点（报告可引用）

### 4.1 会话模型与 TID
服务器常驻 UDP 69 端口只做一件事：收 RRQ/WRQ。每个合法请求创建一个
`TransferSession`（`threading.Thread` 子类），会话内新建 UDP Socket 绑定临时端口
作为本次传输的 TID，此后所有报文严格校验对端地址，防止串扰。

### 4.2 可靠传输机制（异常环境 25 分项）
- **超时重传**：收包超时（默认 2 s）即重发本端最后一个报文；连续 `retries`（默认 6）次失败终止并记录原因；
- **重复 DATA**（我方 ACK 丢失）→ 补发 ACK，不重复写文件；
- **重复 ACK**（我方 DATA 丢失）→ 立即重发 DATA，不等超时；
- **末块宽限**：WRQ 最终 ACK 后保持会话 5 s，客户端重发末块（说明最终 ACK 丢失）则补发 ACK；
- **请求去重**：客户端超时会向 69 端口重发同一请求；仅当该客户端仍有存活会话时忽略，否则允许重建会话（避免"等不到响应"死锁）；
- **完整性验证**：每个传输计算并展示本地文件 MD5，配合丢包工具演示"传得完、传得对"。

### 4.3 块号回绕（大文件）
协议块号为 16 位。内部用无界整数 `seq` 递增，线上块号取 `seq & 0xFFFF`，
新块/重复块判定在回绕处依然正确，突破 65536 × 512 B = 32 MiB 的经典限制
（实测 33 MB 文件经 curl 双向传输 MD5 一致）。

### 4.4 netascii 转换
`NetasciiEncoder/Decoder` 为逐字节状态机，正确处理被 512 字节块边界截断的
CR/LF 序列；行结束统一转换（发送 LF→CRLF、裸 CR→CR NUL；接收反向）。

### 4.5 安全
`PathGuard` 将客户端文件名限制在根目录内：拒绝绝对路径、盘符、`..` 穿越、
Windows 保留设备名；并发用信号量限流；畸形报文一律记录并丢弃。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `tftp` 命令不存在 | Windows 功能里勾选 "TFTP 客户端" 后重开终端 |
| 传输超时无响应 | 检查防火墙是否放行 UDP 69；确认服务器状态灯为"运行中" |
| `tftp.exe` 传大文件失败 | Windows 客户端自身 32 MB 上限（服务端已支持回绕），改用 curl 或 Tftpd64 |
| macOS 绑定 69 失败 | 特权端口，用 `--port 1069` 或 `sudo` |
| 中文文件名乱码 | 服务端按 UTF-8/GBK 自动识别；建议客户端用英文文件名最稳妥 |
| 69 端口被占用 | 任务管理器结束其他 tftpd 进程，或在设置里改端口 |
