# Windows 现场验收联调清单

> 对应《2026秋计网实验检查单-套接字编程实验》。按顺序执行即可覆盖全部检查点。
> 服务器启动：`python server.py`（TFTP UDP 69 + Web 管理台 http://127.0.0.1:8080）。
> 客户端命令均在 **另一台机器**（或本机第二终端）执行。

## 零、准备（一次性）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 0.1 | 拷贝 `tftp-server/` 到 Windows 实验机，确认装有 Python 3.8+ | `python --version` 正常 |
| 0.2 | 启用 Windows TFTP 客户端：控制面板 → 启用或关闭 Windows 功能 → 勾选 **TFTP 客户端** | `tftp` 命令可用 |
| 0.3 | 首次启动 `python server.py`，防火墙弹窗勾选 **专用网络 + 允许** | 状态灯"运行中" |
| 0.4 | 往 `files\` 目录放几个测试文件：1 个小文本（几十字节）、1 个 ~10 MB 二进制、1 个 >32 MB 大文件 | 网页"服务器文件"面板可见 |

## 一、正常上传（20 分）

| # | 操作 | 预期 |
|---|---|---|
| 1.1 | 客户端：`tftp -i <服务器IP> PUT 测试文件.bin` | 网页"进行中的传输"出现 ↑上传条目，结束后落入"历史结果"为绿色**成功**，含平均吞吐量与 MD5 |
| 1.2 | 比对客户端与 `files\` 内文件的 MD5（`certutil -hashfile 文件 MD5`） | 两端 MD5 一致 |
| 1.3 | curl 上传：`curl -T 文件 tftp://<IP>/` | 成功 |

## 二、正常下载（20 分）

| # | 操作 | 预期 |
|---|---|---|

## 三、异常环境可靠传输（25 分）—— clumsy

在 **客户端机器** 以管理员运行 `clumsy.exe`（资料包内含），目标地址填服务器 IP：

| # | 注入方式（clumsy 勾选） | 操作 | 预期 |
|---|---|---|---|
| 3.1 | 掉包 Drop=10%，勾 outbound | 下载 10 MB 文件 | 传输**仍完成**；网页"总重传次数"与该条目"重传"列明显增长；日志逐条记录"等待 ACK 超时，重发 DATA" |
| 3.2 | 掉包 Drop=10%，勾 inbound | 上传 10 MB 文件 | 完成；日志出现"收到重复 DATA，补发 ACK"与"等待 DATA 超时，补发 ACK" |
| 3.3 | 延迟 Lag=500ms | 下载 | 完成，吞吐量下降（符合预期） |
| 3.4 | 重发 Duplicate=10% | 上传 | 完成（服务器补 ACK 处理重复块，不重复写文件） |
| 3.5 | 乱序 Out of order | 下载 | 完成 |
| 3.6 | 每次完成后比对两端 MD5 | — | 全部一致（数据完整性证明） |
| 3.7 | 极端：Drop=30% 下载 | — | 大概率仍完成；若个别失败，历史结果给出"重传 6 次后仍未收到 ACK"原因，再次重试即成功 |

## 常见故障速查

| 现象 | 处理 |
|---|---|
| 客户端超时无响应 | 服务器状态灯是否"运行中"；防火墙是否放行 UDP 69；IP 是否填对 |
| `tftp` 命令不存在 | Windows 功能勾选 TFTP 客户端后**重开命令行** |
| 传输卡在 32 MB | `tftp.exe` 客户端自身限制，大文件用 curl / Tftpd64 |
| 上传报 File already exists | 设置里"允许覆盖已存在文件"被关闭（正是演示项 5.2） |
| clumsy 无法启动 | 需管理员身份运行；仅支持 Windows |
